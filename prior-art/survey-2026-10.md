# Prior art: existing forms of chunk byte references

Snapshot 2026-10-25, from primary sources (specifications, documentation
and source code on default branches). Issue and pull request pages could
not be opened for this snapshot; their state is marked unverified.

## kerchunk and fsspec references

Sources: <https://github.com/fsspec/kerchunk/blob/main/docs/source/spec.rst>,
<https://github.com/fsspec/filesystem_spec/blob/master/fsspec/implementations/reference.py>

- Version 0: flat JSON map, key -> value. A value is a string (inline
  data) or `[url, offset, length]`. Zarr v2 metadata keys may be strings
  or JSON objects.
- Version 1: `{"version": 1, "templates", "gen", "refs"}`. A ref is a
  string (data), `[url]` (whole file) or `[url, offset, length]`.
  `base64:` strings decode to binary. `templates` are jinja strings
  substituted into URLs; `gen` items expand over dimensions as a
  cartesian product. Version 1 expands to version 0.
- Parquet (`LazyReferenceMapper`): `root/.zmetadata` (JSON with
  `metadata` and `record_size`, default 10000) and
  `root/<array>/refs.<N>.parq`. Columns `path` (optional string,
  categorical above a threshold), `offset` (int64), `size` (int64), `raw`
  (optional bytes). The Nth chunk is found by C-order index; files are
  padded to `record_size`.
- Inline: JSON string value, Parquet `raw`. `path` with `size == 0` means
  the whole file. Missing: Parquet `path` and `raw` both null; JSON key
  absent.
- Codecs: only through Zarr v2 `.zarray`. Integrity: none. Grid: Zarr v2
  regular. Addressing: absolute URLs; templates in JSON v1 only.

## VirtualiZarr

Sources: <https://github.com/zarr-developers/VirtualiZarr> (`virtualizarr/manifests/manifest.py`,
`docs/explanation/faq.md`, `docs/explanation/data_structures.md`)

- `ChunkManifest`: string paths, uint64 offsets and lengths, each shaped
  like the chunk grid; a sparse map of inlined chunk bytes.
- Sentinels: missing chunk path `""`; inlined chunk path `"__inlined__"`.
  Zero-length references rejected.
- `ManifestArray` pairs Zarr v3 array metadata (regular chunk grid, codec
  chain) with one manifest.
- Writes kerchunk (dict, JSON, Parquet; default `record_size` 100000) and
  Icechunk (with `last_updated_at` used as the chunk checksum).
- Stated limits: one chunk shape per array (variable chunks planned), one
  codec chain per array, codecs must be registered with Zarr, a known
  pitfall merging CF `scale_factor` and `add_offset`.

## Icechunk

Sources: <https://github.com/earth-mover/icechunk> (`icechunk-format/flatbuffers/manifest.fbs`,
format specification 2.1, `docs/docs/guides/virtual.md`)

- `ChunkRef`: `index` (chunk coordinates), `inline` (encoded bytes),
  `offset`, `length`, `chunk_id` (native), `location` (virtual, absolute
  URL), and at most one of `checksum_etag` or `checksum_last_modified`.
- Which fields are set decides the ref type: inline, native or virtual.
- Refs sorted by index; an array's refs may span several manifests;
  locations may be dictionary-compressed.
- Integrity is enforced: reads send `If-Match` or
  `If-Unmodified-Since`; a failed precondition is an error.
- Virtual chunk containers authorise access by URL prefix; named
  containers allow relative locations resolved against the prefix.
- Codecs in Zarr v3 array metadata. Missing chunks: an absent ref
  (not confirmed in specification text).

## DMR++ (OPeNDAP)

Sources: <https://github.com/OPENDAP/bes/tree/master/modules/dmrpp_module>

- XML DAP4 metadata with a `dmrpp` namespace; `dmrpp:href` names the data
  file.
- Per variable `dmrpp:chunks` with `compressionType` (ordered filter
  pipeline, repeats allowed), `fillValue`, `byteOrder`, then
  `chunkDimensionSizes`.
- Per chunk `offset`, `nBytes`, `chunkPositionInArray` (element indices),
  filter mask, optional per-chunk `href`.
- Inline: `dmrpp:compact` (base64). Missing: chunk omitted, fill used.
  Multi-block chunks supported. Integrity: none.

## Zarr proposals

- Chunk manifest storage transformer: zarr-specs issue 287, "Manifest
  storage transformer (v3 storage transformer)", proposed by jhamman (cited
  by VirtualiZarr). Open/closed state unverified (see note below); in the
  thread the author says his effort has moved to Icechunk. Nothing
  registered under
  zarr-extensions storage transformers.
- Variable chunking: ZEP 3, draft since 2022.
- `rectilinear` chunk grid: <https://github.com/zarr-developers/zarr-extensions/blob/main/chunk-grids/rectilinear/README.md>.
  Per axis an integer (regular) or a list of edge lengths, with run-length
  pairs. Experimental in zarr-python, off by default.

## GDAL

Sources: `gcore/gdal.h`, `gcore/multidim/` on <https://github.com/OSGeo/gdal>

- `GDALMDArray::GetRawBlockInfo` and C `GDALMDArrayGetRawBlockInfo`, since
  3.12. Fields: filename, offset, size, driver info key/values, inline
  data (filename and offset null when set). A missing block returns
  success with every field empty.
- Info keys: `ENDIANNESS`; HDF5 and netCDF add `COMPRESSION`, `FILTER`;
  Zarr adds compressor and filters JSON and `TRANSPOSE_ORDER`.
- Implemented for HDF5, netCDF, Zarr and VRT (VRT only with declared block
  size and one matching source per block).
- Draft `gdal mdim get-refs` subcommand (OSGeo/gdal pull request 14677,
  "Add gdal mdim get-refs algorithm"; open/closed state unverified, its
  review checklist still unticked at the 2026-10-25 check): attribute-only vector layer with `dim_0..dim_{n-1}`,
  `present`, `path`, `offset`, `size`, `info`; layer metadata with array
  name, data type, dimensions and codec. Absent rows have null path,
  offset and size; inline planned.

## TIFF and COG

- `TileOffsets` (tag 324), `TileByteCounts` (325), `JPEGTables` (347).
- Sparse tiles (GDAL `SPARSE_OK`): offset and byte count 0.
- virtual-tiff (<https://github.com/virtual-zarr/virtual-tiff>): a
  VirtualiZarr parser that turns tile or strip offsets into a chunk
  manifest per IFD; relies on Icechunk entity tags for drift detection;
  JPEG with shared tables not supported.

## Other

- h5py `DatasetID.get_chunk_info` and `chunk_iter`: chunk offset, filter
  mask (per chunk), byte offset, size; unallocated chunks have no offset.
- zarrita.js `ReferenceStore`: kerchunk version 0 entries; no templates or
  Parquet support found.
